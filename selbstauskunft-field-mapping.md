### How to read the tables

- **Field key / ID** is the `id` of the control; for radio groups it is the `name` of the radio inputs. Fields inside `<template>` cards get generated ids at runtime (`ctl-n`, `radios-n`), so the template id is given instead.
- **Input type** is the HTML shape: `currency (€)` = text input with `inputmode="decimal"` and a „€“ suffix, formatted `1.234,56` on blur; `number (m²)` etc. = text input with `inputmode` and a unit suffix; `year` = text input with placeholder `jjjj`; `date` = text input with placeholder `tt.mm.jjjj` and the prototype's own date picker; `radio` = the chip-style `.choices` group; `select` = native dropdown.
- **Required** = `required` attribute on the control, or `data-required` on a radio group. A required field inside a conditional block is only enforced while the block is open („yes (when shown)“). Validation messages are the same everywhere and therefore not repeated per row: required text/select controls show **„Dieses Feld wird für den Antrag benötigt“** on blur; required radio groups show **„Bitte wählen Sie eine Option“** on submit; the footer counter reads „Noch n Pflichtfelder offen“ / „Alle Pflichtfelder vollständig“.
- **Options** are listed in display order, separated by „;“. The first entry „Bitte wählen“ is the empty value of every select.
- **Info text** = the `.help` paragraph, which the prototype renders as an info icon with a tooltip bubble (same text). `Placeholder:` and `Unit suffix` are listed in the same column.
- **Conditional logic** names the controlling question by its label. Rows for nested conditions carry the full chain.
